# coursekit roadmap

The forward-looking view.
For the detailed record — measurements, dated decisions, per-course results — see the working log (kept offline).
This file is the map; the log is the diary.

## Vision

> coursekit turns a course's own material into Canvas-ready artifacts that are **correct, well-taught, and reviewable** — locally, and measurably.

Every decision checks against that line: does it make artifacts more correct, better-taught, more reviewable, or the tool more usable to a real instructor?
If not, it goes to the parking lot.

## How we work (the cadence)

1. **One active focus at a time.** A single _current milestone_ (below). Everything else waits.
2. **Parking lot.** A new idea gets written down immediately so it is never lost — and is **not acted on** until a regroup. Ideas are welcome; acting on them mid-focus is not.
3. **Every milestone has a "done when."** A concrete, ideally measurable acceptance (e.g. "recall > X", "5/5 discrimination", "the review runs from one command"). No open-ended work.
4. **Regroup at milestones.** When the current thing lands: review the parking lot, re-prioritise, pick the next focus. Only then.

## Structure & numbering

The forward view is organized by **capability area**, with a stable semantic ID on every item.

- **ID = `AREA-N[.M]`** — `AREA` is the capability; `N` is **do-order within that area** (1 = do-first; a sequence, not a priority score); `.M` a sub-step. IDs are stable; horizon/status move.
- **Horizon** (when, across areas): `H0` now · `H1` next · `H2` later · `H3` someday/research.
- **Status:** ✅ shipped · 🔶 partial · ⬜ open · ✨ proposed-gap · 🧭 new-capability (2026-08-06 expansion).
- The **outline below** is the structured view; the **Detail — dated history** section keeps each item's full record, tagged with the same ID. New items (✨/🧭) live only in the outline until worked.

- `PAGE-13 · H2 · ✨` **The flexible-generation request space — SCOPE × ARTIFACT × GROUNDING** (user, 2026-08-07; generalizes PAGE-10 + ASMT-17 across pages AND quizzes). A week's knowledge is used many ways — a technical quiz vs an open aesthetic question; a technical-review summary vs a whole-week page; a glossary; an artist list or bibliography NOT in the lecture. Three orthogonal axes: **(1) SCOPE** — whole week · one SOURCE (ASMT-17 ✅) · a set of CONCEPTS (the concept map + segmentation already make this addressable) · a TYPE-slice (technical vs aesthetic/interpretive — a classification layer we lack, ⇐ EVAL-3 / vocabulary typology). **Key finding:** a FLAT consolidated `week-N.md` is NOT addressable enough for the type/concept slices — consolidation gives GROUNDING; the CONCEPT MAP (+ source headers + a type tag) is the INDEX that makes "quiz on Y, page on X" possible. So FLOW-2 consolidation must PRESERVE source structure, not flatten it. **(2) ARTIFACT** — teaching page · summary/review · quiz · glossary · overview · bibliography · exemplar/artist list (the page FUNCTION axis + assessment types). **(3) GROUNDING** — from-source (default) · instructor-SUPPLIED (a bibliography/artist list "not in the lecture" is CURATED via supplements — grounded in the instructor, never fabricated) · model-SUGGESTED-and-flagged (an opt-in "draft me further reading" mode, marked UNVERIFIED — scores 0 on EVAL-15 by design). **coursekit must NEVER silently fabricate references/citations** (the no-URL/no-invention guard). Ties PAGE-10, ASMT-17, EVAL-3, EVAL-15, and supplements.
  **Deepened 2026-08-07 (user — the axes are MEASURES, not just knobs; the epistemic model).** Each axis is a *measured relationship*, and each maps to an evaluator coursekit already has or is building: **SCOPE** = the extent of the field the material implies → measure = **coverage** of the concept map (the map is a *sample* of a larger field; how much of the space is present). **ARTIFACT** = how well an artifact illuminates the scope → measure = **concept-delivery** (does it teach the concepts, PAGE concept_delivery) crossed with **groundedness** (is it evidenced by the source, EVAL-15). **GROUNDING** = the interface between FACULTY knowledge and LLM knowledge, both fallible — LLM knowledge *measured* (never assumed bad), faculty knowledge *respected but not infallible* → measure = EVAL-15 groundedness + surfacing where model and material *disagree* (the "faculty isn't infallible" half). So the three axes are the three checks the evaluator arc has been converging on: coverage · concept-delivery · groundedness. **Epistemic models it reflects** (none is a perfect fit; the synthesis is the contribution): Toulmin's argument model (claim/grounds/warrant — the artifact↔grounding "is it evidenced?" relation); backward design / UbD (scope → evidence → learning — the scope↔artifact relation, already coursekit's frame via enduring understandings); **social epistemology / reliabilism / the epistemology of testimony** (the grounding axis IS this — two knowledge *sources*, neither infallible, trust *calibrated* rather than assumed — the deepest fit); **RAG faithfulness/attribution** (the technical instantiation of the grounding measure = EVAL-15); and HCI's **calibrated trust / appropriate reliance / human-AI complementarity** (the goal is not the model replacing faculty judgment but a faculty member *seeing* how the two knowledges relate). **The distinctive move — coursekit's actual thesis:** treat the faculty↔LLM epistemic relationship as a *first-class, measured, represented* object for a "cognizant faculty" — not "is the AI right" (facticity alone) but "how do the two knowledges relate, and can the instructor SEE that relationship." That reframes coursekit from a generator-with-a-checker into an *epistemic instrument*.
