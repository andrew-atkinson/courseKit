# Component catalog

> Generated from `coursekit/generate/catalog.py` — edit there, then run `python -m coursekit.generate.catalog`. Do not edit this file by hand.

The components a page (later: any content type) is composed from. Each earns its place by serving a **pedagogic function** — the design that serves none doesn't ship.

## Pedagogic functions

The CLT + UDL frames a component can serve; composition and evaluation reason about these.

- **exposition** — Explain an idea in prose — the base narrative act.
- **chunking** — CLT segmenting — break content into working-memory-sized, labelled pieces.
- **signalling** — CLT — foreground the one thing that matters; the reserved accent.
- **contrast** — CLT — place two things side by side (wrong-way/right-way, before/after).
- **type-distinction** — Cut 'what am I reading?' load by naming a unit's type (UDL representation).
- **worked-example** — Show the doing — a concrete, followable example.
- **retrieval** — Testing effect — make the student predict/recall before revealing.
- **representation** — UDL multiple means — a non-prose channel (visual) for the same idea.
- **engagement** — UDL — hook and motivate; give a reason to care.
- **action** — UDL — invite the student to try it.
- **reference** — Look-up material — terms and definitions to review.

## Content types

The artifacts these components compose into; each component's **Used in** says which apply.

- **page** — A teaching, reference, or orientation page (page.json). (11 components)

## Components

### `heading` — Section heading
- **Serves:** chunking, signalling
- **What:** Opens a titled section and marks what KIND of section it is.
- **Use when:** Start each concept/section; assign a role so students can scan the page's shape.
- **Avoid:** Never leave a heading with no content before the next heading — it renders as an empty panel.
- **Fields:** text, level (1–4), role?
- **Variants:** role: review · concept · practice · example · summary
- **Used in:** page

### `paragraph` — Paragraph
- **Serves:** exposition
- **What:** A paragraph of teaching prose (markdown).
- **Use when:** Explain one idea — one idea per paragraph.
- **Avoid:** Don't stack many long paragraphs with no device between them (crowds the reader).
- **Fields:** text (markdown)
- **Used in:** page

### `bullets` — Bulleted list
- **Serves:** chunking
- **What:** A short list of parallel points.
- **Use when:** Enumerate steps, key takeaways, or parallel items.
- **Avoid:** Not for prose fragmented into bullets, and not for comparisons (use columns).
- **Fields:** items[]
- **Used in:** page

### `code` — Code block
- **Serves:** worked-example, representation
- **What:** A literal, fenced code sample.
- **Use when:** Show the actual code the material teaches — only when the material actually contains code; introduce it with a sentence first.
- **Avoid:** Never two code blocks back to back with no prose between; never invent code not in the material.
- **Fields:** code, language
- **Used in:** page

### `glossary` — Glossary
- **Serves:** reference
- **What:** Term/definition pairs for review.
- **Use when:** Collect a section's or a week's key terms for look-up.
- **Avoid:** Not a substitute for teaching a term in context the first time it appears.
- **Fields:** entries[] (term, definition)
- **Used in:** page

### `callout` — Callout
- **Serves:** signalling
- **What:** A set-apart note, tip, or warning.
- **Use when:** Flag a pitfall (warning), an aside (note), or a pro-tip (tip).
- **Avoid:** Sparingly — overuse drains the signal it depends on.
- **Fields:** text, tone
- **Variants:** tone: note · tip · warning
- **Used in:** page

### `columns` — Comparison columns
- **Serves:** contrast
- **What:** 2–3 side-by-side lists for comparison.
- **Use when:** Wrong-way/right-way, before/after, or option A vs B.
- **Avoid:** Not for a single list (use bullets); code reads poorly as bulleted lines.
- **Fields:** columns[] (title, items[])
- **Used in:** page

### `pullquote` — Pull quote
- **Serves:** signalling
- **What:** The one key idea, foregrounded.
- **Use when:** Once per page — the week's enduring understanding.
- **Avoid:** More than one per page dilutes the signal.
- **Fields:** text, attribution?
- **Used in:** page

### `card` — Typed card
- **Serves:** type-distinction, representation
- **What:** A titled, self-contained unit whose type is visible.
- **Use when:** Distinguish a concept / example / takeaway as its own visible unit.
- **Avoid:** Don't card ordinary prose — reserve it for a genuinely distinct unit.
- **Fields:** title, text, card_kind
- **Variants:** card_kind: concept · example · takeaway
- **Used in:** page

### `details` — Disclosure / retrieval
- **Serves:** retrieval, chunking
- **What:** A predict-before-reveal foldout (native <details>, no JS).
- **Use when:** A 'Predict: …' recall prompt, or optional depth ('Going deeper').
- **Avoid:** Don't hide essential content behind a fold; a hollow foldout to satisfy a gate is worse than none.
- **Fields:** summary (the visible prompt), text (the revealed content)
- **Used in:** page

### `image` — Inline image
- **Serves:** representation
- **What:** A visual placed inline where it teaches (the instructor supplies the file).
- **Use when:** A diagram, example work, or chart the material shows — place the ref where it belongs.
- **Avoid:** Never emit a URL (the model fabricates them); alt text is required or the image is dropped.
- **Fields:** ref, alt (required), caption?
- **Used in:** page
